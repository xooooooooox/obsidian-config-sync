# 待裁决:本轮不修的冲突与判断题

Date: 2026-08-19 · 出自 2.24.2 注释与文档专项迭代

本轮的规矩是「文档与代码冲突以代码为准」。勘察发现的 9 处漂移全部是文档追不上代码,已按代码
改完文档。这份表记的是**另一类**:改法需要你拍板,或者可疑的是代码本身。本轮一律只记不动。

## 1. 已知违反不变量 II.4 的代码

| 项 | 位置 |
|---|---|
| 文档主张 | `docs/ARCHITECTURE.md`,Storage invariants 一节:`refreshBratIndex` 的 guard 只覆盖空列表 |
| 代码实况 | `src/main.ts:1408` |

这不是漂移:文档如实记录了一个未决问题,描述与代码完全一致。只有一个 BRAT repo 的设备在写入
时仍会剪掉其余九个的条目,而它由 Beta 标签页的 render 触发,背后没有用户手势。把 guard 从
「什么都不知道」收窄到「知道的比索引少」是一次真改动,不属于本轮范围。

**要你定的是**:收口,还是把它留在文档里继续如实记录。

## 2. 讲历史的测试名

约 8 个 `it("no longer …")` 形式的测试名,例如 `tests/itemCard.test.ts`、
`tests/enablementRow.test.ts`、`tests/companions.test.ts`。它们和注释犯的是同一个毛病:测试名
说的是「这次改动修好了什么」,而不是「这段代码保证什么」。

本轮**没动**,因为改测试名会动断言之外的代码文本,越过了「不改代码」这条线。

**要你定的是**:是否单开一次改名,以及是否连带把 `Before the change,` / `After the change,`
这类测试内注释一起收(那部分注释本轮已经改了)。

## 3. 注释里的版本号:哪些算线上事实,哪些算历史

规则说常青文档里的版本号只在描述「本构建今天仍须容忍的线上兼容事实」时才留得住。`src/` 注释里
有两类落在这条线附近,我按**保留**处理了,请你确认这条界线画得对:

- **混版兼容注释,约 15 处**(`src/core/status.ts`、`src/core/manifest.ts`、
  `src/core/leftover.ts`、`src/core/ConfigSyncCore.ts`、`src/main.ts`)。形如「一个由 2.21.0 设备
  写出的 remote 是过渡期的正常状态」。按规则字面它们含版本号,但那个版本号是**本构建今天必须
  容忍什么**的一部分,删掉之后读者无法判断这段兼容代码为何存在。
- **迁移模块里描述旧形状的注释,约 10 处**(`v2Migration.ts`、`v4Migration.ts`、
  `settingsMigration.ts`、`leftover.ts`)。描述退役形状是这些文件的**正业**,不是它们的历史。

判据是那句老话:删掉这句话之后,读者判断这条规则是否成立的能力有没有下降?两类我都判为「会
下降」,所以留。你若认为该一并清掉,说一声。
